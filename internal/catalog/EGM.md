# catalog

## Overview
Package `catalog` implements EdgeFetch's pure-CPU e-commerce sanitization, Shopify and WooCommerce product/feed normalization, polite storefront catalog pagination, deterministic FNV-1a 64-bit snapshot hashing and diffing, `>50%` shrink-guard detection, Universal Commerce Protocol (UCP) endpoint discovery, record filtering, and bounded `32 MiB` multi-tenant catalog state. All files compile cleanly under both native builds and `GOOS=wasip1 GOARCH=wasm` without importing `net/http`, `crypto/tls`, or `crypto/x509`.

## Interface
- `[types.go:CatalogRecord]`, `[types.go:CatalogVariantRecord]`, `[types.go:LeanCatalogRecord]`, `[types.go:DeclarativeCatalogConfig]`: Canonical platform-neutral product, variant, lean projection, and declarative catalog pagination structs.
- `[commerce.go:SanitizeCommerceField]`, `[commerce.go:SanitizeCommerceTimestamp]`, `[commerce.go:NormalizePublicCommerceImageURL]`, `[commerce.go:IsSafePublicHostname]`: Non-destructive untrusted commerce field/timestamp sanitizers and public `https://` port-443 image URL validator.
- `[shopify.go:IsShopifyHTMLOrHeaders]`, `[shopify.go:ExtractShopifyCurrencyFromHTML]`, `[shopify.go:ResolveCustomDomainShopifyProductTwinURL]`, `[shopify.go:NormalizeShopifyProductRecord]`, `[shopify.go:EnrichShopifyProductFromJSON]`, `[shopify_html.go:FormatShopifyProductsFeedTwin]`, `[shopify_html.go:ExtractShopifyProductHTML]`: Shopify storefront detection, twin URL resolution, JSON/Ajax `.js` product normalization, feed formatting, and post-fetch HTML extraction.
- `[woocommerce.go:IsWooCommerceHTMLOrHeaders]`, `[woocommerce.go:ResolveCustomDomainWooCommerceProductTwinURL]`, `[woocommerce.go:NormalizeWooCommerceProductRecord]`, `[woocommerce.go:EnrichWooCommerceProductFromStoreAPI]`, `[woocommerce.go:FormatWCStoreAPIListTwin]`, `[woocommerce.go:FormatWCStoreAPIProductTwin]`, `[woocommerce_html.go:ExtractWooCommerceProductHTML]`: WooCommerce Store API v1 detection, minor-unit price scaling, twin enrichment, and post-fetch HTML extraction.
- `[woocommerce_html.go:ValidateDeclarativeCatalogConfig]`, `[woocommerce_html.go:CatalogSpecFirstPage]`, `[woocommerce_html.go:CatalogSpecParsePage]`, `[woocommerce_html.go:CatalogSpecNextPage]`: Declarative catalog pagination URL builders and strict JSON batch parsers for `"shopify"` and `"woocommerce"`.
- `[snapshot.go:ProjectLeanCatalogRecord]`, `[snapshot.go:ComputeCatalogVariantHash]`, `[snapshot.go:ComputeCatalogProductHash]`, `[snapshot.go:BuildSnapshotHashBundle]`, `[snapshot.go:ComputeCatalogSnapshotDiff]`, `[snapshot.go:ComputeDetailedCatalogSnapshotDiff]`, `[snapshot.go:EvaluateShrinkGuard]`, `[snapshot.go:ApproxHashBundleBytes]`, `[snapshot.go:ClampCatalogRecord]`: Lean record projection, timestamp-independent product/variant hashing, diffing, `>50%` shrink guard, memory footprint estimation, and `<= 64 KiB` per-record clamping.
- `[catalog_parse.go:DiscoverUCPEndpointFromRobots]`, `[catalog_parse.go:IsSafeHTTPSStoreURL]`, `[catalog_parse.go:InitCatalogPullPlan]`, `[catalog_parse.go:EvaluateCatalogPageResponse]`, `[catalog_filter.go:FilterCatalogRecords]`: Storefront URL validation, UCP discovery, WAF/non-storefront page evaluation, `auto` Shopify-to-WooCommerce fallback, and multi-attribute record filtering/slicing.
- `[store.go:CatalogStore]`, `[store.go:NewCatalogStore]`, `[store.go:FetchFunc]`: Thread-safe bounded `32 MiB` multi-tenant LRU store, owner-reserved concurrency admission (`6/8` non-owner cap, `2` per principal), origin currency cache, and singleflight `<= 2` gunzip reload coordinator for Phase 3's Go `--mode=hub`.

## Invariants
- `[commerce.go:SanitizeCommerceField]`, `[commerce.go:SanitizeCommerceTimestamp]`: Strips ANSI CSI sequences and Unicode tag/bidi smuggling runes, collapses line breaks, non-destructively escapes `&`/`<`/`>`, neutralizes `javascript:`/`vbscript:`/`data:`/`file:`/`blob:` inline links, and escapes Markdown punctuation (`[`, `]`, `*`, `_`, `~`, `` ` ``, `#`) while preserving product tokens like `<USB-C>` and pipe characters in SKU fields.
- `[commerce.go:NormalizePublicCommerceImageURL]`, `[catalog_parse.go:IsSafeHTTPSStoreURL]`: Enforces `https://` on port `443` with zero credentials, rejecting `localhost`, `.local`, `.internal`, DNS-rebinding suffixes, bare public suffixes (`extract.IsPublicOrPrivateSuffix`), IPv4/IPv6/decimal/octal/hex IP literals, and recursive `selfHost` URLs.
- `[shopify.go:NormalizeShopifyProductRecord]`, `[woocommerce.go:NormalizeWooCommerceProductRecord]`, `[snapshot.go:ClampCatalogRecord]`: Deduplicates image URLs in `O(N)` time, caps images and variants at `<= 250` per product, omits `descriptionText` and `images` in `"lean"` mode while emitting `""` and `[]` in `"full"` mode, and clamps serialized records to `<= 64 KiB`.
- `[snapshot.go:ComputeCatalogProductHash]`, `[snapshot.go:EvaluateShrinkGuard]`: Explicitly excludes `updatedAt` and `publishedAt` from product hashes so inventory timestamp bumps never produce false `changed` counts, and flags `warning: "shrink"` whenever a snapshot falls strictly below `50%` of the prior complete baseline.
- `[catalog_parse.go:EvaluateCatalogPageResponse]`: Halts immediately on cross-origin redirects, `robots.txt` / `Content-Signal` blocks, and WAF/challenge interstitials (`status: "challenged"`), while allowing `platform: "auto"` to fall back from Shopify `404`/`400`/`405` or plain non-storefront HTML to WooCommerce and exit cleanly with `reason: "unsupported_storefront"`.
- `[store.go:CatalogStore]`: Enforces per-user fair-share isolation (`8 MiB`, `4` cached runs) before global `32 MiB` eviction, reserves `2` of `8` global catalog slots for `owner`, and bounds cold gzipped NDJSON reloads to `<= 2` concurrent decompressions and `<= 32 MiB` decompressed bytes.

## Side Effects
- `[store.go:GenerateCatalogID]`: Reads 8 random bytes from `crypto/rand.Reader`. All other functions in `internal/catalog` are pure in-memory computations (or invoke caller-supplied `FetchFunc` callbacks).
